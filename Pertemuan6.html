Bagian I

Ketergantungan TI

Saat Kabel dan Server Menjadi Penentu Hidup-Matinya Bisnis.

Realita Arsitektur

Mitos "Aplikasi Berdiri Sendiri"

  • Pengguna hanya melihat antarmuka (UI/UX) di layar ponsel.
  • Namun di baliknya, sebuah klik "Beli" menggerakkan puluhan server, sakelar jaringan, dan basis data terdistribusi.
  • Jika satu kabel putus, seluruh proses bisnis terhenti.

4 Lapisan Fondasi Infrastruktur TI Bisnis

1. Perangkat Komputasi

Server fisik, mesin virtual (VM), kontainer mikro, dan storage array.

2. Jaringan & Bandwidth

Router, Switch, Firewall, Fiber Optic, dan bandwidth ISP penyedia.

3. Layanan Cloud & Middleware

API Gateway, Web Server Nginx, Message Broker (Kafka/RabbitMQ).

4. Terminal Endpoint

Mesin kasir POS, scanner barcode gudang, tablet barista, PC staf kantor.

Model Tradisional

On-Premise Server

  • Server fisik dibeli dan disimpan di ruang server kantor sendiri.
  • Perawatan, listrik, genset, dan AC pendingin ditanggung tim lokal.
  • Kontrol data 100% internal, namun biaya modal awal (Capex) sangat tinggi.

Model Modern

Cloud Infrastructure

  • Menyewa komputasi dari penyedia global (AWS, GCP, Azure, Alibaba).
  • Elastis: server otomatis bertambah saat pesanan melonjak.
  • Ketergantungan absolut pada stabilitas koneksi internet.

Risiko Operasional Pada Model On-Premise

"Banyak toko ritel meletakkan komputer server kasir di bawah meja kasir tanpa UPS. Saat listrik padam 1 detik, basis data kasir mengalami korupsi data (*data corruption*) dan transaksi macet berjam-jam."

Studi Kasus Ritel

Dilema Kasir Berbasis Cloud

  • Toko kopi menggunakan aplikasi POS Android berbasis cloud.
  • Pukul 12.30 WIB (Jam makan siang sibuk), kabel fiber optik di jalan terputus truk kontainer.
  • Kasir tidak bisa input pesanan, QRIS gagal cetak, pembeli membubarkan diri.

Pentingnya SOP Cadangan (*Fallback Procedure*)

Mode Offline Sinkronisasi

Aplikasi kasir harus memiliki cache lokal agar tetap bisa mencatat transaksi saat internet terputus, lalu otomatis sinkronisasi saat online.

Koneksi Dual-WAN Failover

Router kafe/kantor dipasang modem kartu seluler 4G/5G otomatis beralih jika kabel fiber optik utama putus.

"BPMN memodelkan alur logika manusia, namun infrastruktur TI menentukan apakah logika tersebut mampu bertahan di dunia nyata."

Bagian II

Pemetaan Aliran Data

Melacak Perjalanan Data: Dari Input Hingga Penyimpanan Persisten.

Siklus Hidup Informasi

3 Titik Kritis Aliran Data

  • **Data Ingestion (Masuk):** Validasi format input dari formulir atau sensor.
  • **Data In-Transit (Bergerak):** Transmisi data antar server melalui protokol HTTPS/API.
  • **Data At-Rest (Diam):** Penyimpanan aman di basis data relational / objek.

Bahaya "Silo Data" di Organisasi

Silo Data (Terisolasi)

Departemen Gudang mencatat stok di Excel lokal, kasir mencatat di kasir cloud terpisah. Hasil: Kasir menjual barang yang fisiknya sudah habis di gudang.

Terintegrasi (Enterprise Bus)

Setiap transaksi kasir langsung memicu *event* pembaruan stok secara *real-time* ke basis data gudang menggunakan webhook atau pesan antrean.

Konektor Antar Sistem

Application Programming Interface (API)

  • Pintu kontrak resmi pertukaran data antar aplikasi berbeda.
  • Contoh: Toko Kopi ITBS memanggil API Bank BCA untuk mengecek mutasi transfer QRIS secara otomatis tanpa repot cek mutasi manual.

Menghubungkan Aliran Data ke BPMN 2.0

Data Input & Output

Menempelkan ikon Data Object ke Task dengan panah berarah untuk memperlihatkan berkas masukan dan luaran.

Data Store Reference

Memetakan tabel basis data mana yang dibaca (*read*) dan diperbarui (*write*) oleh masing-masing lane kerja.

Hambatan Fisik Jaringan

Throughput & Latency

  • **Throughput:** Kapasitas volume pipa data per detik (Mbps / Gbps).
  • **Latency:** Jeda waktu yang dibutuhkan paket data untuk bolak-balik dari ponsel ke server.
  • Latency di atas 500ms membuat kasir lambat merespons pembeli, memicu frustrasi antrean.

Risiko Transaksi Gagal (*Concurrency Issue*)

"Dua pelanggan membeli 1 porsi roti bakar terakhir pada detik yang sama di GoFood dan di kasir langsung. Jika sistem tidak memiliki mekanisme *database locking*, kedua transaksi akan disetujui, dan staf dapur akan kewalahan karena roti fisiknya hanya tersisa satu."

Solusi Arsitektur

Antrean Pesan (*Asynchronous Messaging*)

  • Daripada server langsung crash saat menerima 10.000 pesanan serentak, pesanan ditampung dalam antrean (*Queue*).
  • Sistem dapur memproses pesanan satu per satu sesuai urutan antrean tanpa kehilangan data.

Bagian III

Service Level Agreement

Menjamin Ketersediaan Sistem & Menghitung Kerugian Downtime.

Kontrak Kinerja

Apa itu SLA?

  • Perjanjian formal antara penyedia layanan TI dengan unit bisnis mengenai target performa minimum.
  • Mencakup metrik: **Uptime**, **Waktu Respons Transaksi**, dan **Waktu Pemulihan Bencana**.

Memahami Standar Ketersediaan (*High Availability*)

99% Availability ("Two Nines")

Toleransi Downtime: 3,65 Hari / Tahun

Terlalu buruk untuk platform pembayaran digital atau rumah sakit.

99.9% Availability ("Three Nines")

Toleransi Downtime: 8,76 Jam / Tahun

Standar umum untuk aplikasi e-commerce dan operasional ritel harian.

99.99% Availability ("Four Nines")

Toleransi Downtime: 52,6 Menit / Tahun

Standar perbankan nasional, telekomunikasi inti, dan server bursa saham.

Dua Metrik Kunci Kegagalan

MTBF vs MTTR

  • **MTBF (Mean Time Between Failures):** Rata-rata durasi sistem berjalan lancar sebelum terjadi kerusakan berikutnya. Semakin lama, semakin tangguh.
  • **MTTR (Mean Time to Recover):** Berapa lama tim IT membutuhkan waktu untuk memperbaiki server down hingga sistem hidup kembali.

Single Point of Failure (SPOF)

"SPOF adalah satu komponen tunggal pada sistem infrastruktur yang jika mengalami kegagalan, maka SELURUH sistem bisnis akan langsung mati total."

Contoh: Sebuah kantor memiliki 50 komputer modern, tetapi hanya memiliki 1 kabel colokan listrik utama tanpa UPS cadangan.

Menghilangkan SPOF

Prinsip Redundansi (Pencadangan)

  • Menyediakan salinan komponen cadangan yang siap menggantikan seketika (*Hot Standby*).
  • Penyediaan dua unit UPS listrik ganda.
  • Berlangganan dua ISP internet berbeda (misal: Telkom IndiHome + Biznet).

Berapa Kerugian Finansial Saat Server Mati?

1. Kehilangan Pendapatan Langsung

Pelanggan beralih memesan makanan ke kompetitor saat aplikasi gerai mengalami error.

2. Gaji Karyawan Menganggur

Staf dapur dan barista tetap dibayar per jam, namun tidak bisa membuat kopi karena ketiadaan data tiket.

3. Rusaknya Reputasi Merek

Ulasan bintang satu bertebaran di Google Maps akibat kekecewaan pelanggan yang antre lama.

Rencana Kontinjensi

Disaster Recovery Plan (DRP)

  • Prosedur pemulihan ketika pusat data mengalami musibah banjir, kebakaran, atau serangan siber.
  • **RPO (Recovery Point Objective):** Batas usia data cadangan yang boleh hilang (misal: cadangan tiap 1 jam).
  • **RTO (Recovery Time Objective):** Batas waktu maksimal sistem harus sudah hidup kembali (misal: maksimal 2 jam).

Refleksi Cepat

"Jika SLA server KRS kampus menjanjikan uptime 99%, apakah mahasiswa puas jika portal down selama 3 hari di masa pengisian KRS?"

Tentu TIDAK. Kebutuhan operasional akademik membutuhkan ketersediaan tinggi di momen kritis!

Kuis Pemahaman Formatif

Kuis Evaluasi • Soal 1/4

Apa kepanjangan dan tujuan dari Service Level Agreement (SLA)?

A. Perjanjian tingkat layanan minimum antara penyedia TI dan pengguna bisnis.
B. Lisensi perangkat lunak open-source untuk kompilasi kode program.
C. Standar penggajian teknisi jaringan telekomunikasi.

Pembahasan: A

SLA (Service Level Agreement) adalah dokumen kontrak yang menetapkan standar kinerja minimum, waktu respons, dan target uptime sistem TI.

Kuis Evaluasi • Soal 2/4

Apa bahaya utama dari keberadaan Single Point of Failure (SPOF) pada proses bisnis?

A. Menyebabkan kecepatan internet komputer menjadi terlalu tinggi.
B. Jika satu komponen tersebut rusak, seluruh operasional bisnis langsung lumpuh total.
C. Meningkatkan biaya tagihan listrik di server lokal.

Pembahasan: B

SPOF tidak memiliki jalur cadangan. Kerusakan pada titik tunggal ini secara instan memutus mata rantai proses bisnis organisasi.

Kuis Evaluasi • Soal 3/4

Teknologi apa yang menjadi jembatan penghubung pertukaran data antar sistem aplikasi yang berbeda platform?

A. Flashdisk USB Fisik
B. Application Programming Interface (API)
C. Monitor VGA Komputer

Pembahasan: B

API memungkinkan dua sistem berbeda (misal: Tokopedia dan Bank BCA) saling mengirimkan informasi dan memvalidasi pembayaran secara terstandar.

Kuis Evaluasi • Soal 4/4

Apa kepanjangan dari MTTR dalam manajemen pemeliharaan sistem?

A. Maximum Time to Restart
B. Mean Time to Recover / Repair
C. Minimum Traffic Total Rate

Pembahasan: B

MTTR mengukur rata-rata durasi yang dibutuhkan tim teknis untuk memulihkan kembali sistem setelah terjadi gangguan (*downtime*).

Evaluasi Konseptual Selesai

Pemahaman mengenai ketergantungan infrastruktur ini adalah bekal krusial sebelum kita masuk ke aspek keamanan informasi (*Security-Aware Process*) di Pertemuan 7.

Checklist Penilaian Infrastruktur bagi Analis

  • Apakah setiap task digital memiliki ketergantungan koneksi internet yang jelas?
  • Apakah basis data dilindungi oleh mekanisme backup otomatis harian?
  • Apakah ada prosedur manual jika sistem cloud sewaktu-waktu mengalami gangguan?
  • Apakah SLA pihak ketiga (API Payment/Logistik) telah dipahami oleh manajemen?

Ringkasan Utama Hari Ini

1. Proses bisnis modern mustahil dilepaskan dari infrastruktur TI (server, jaringan, cloud).
2. Aliran data yang lancar mencegah terjadinya *silo data* dan inkonsistensi transaksi antar bagian.
3. Eliminasi *Single Point of Failure (SPOF)* melalui redundansi adalah kunci menjaga SLA ketersediaan tinggi (*High Availability*).

Tanya Jawab Umum 1

"Pak, apakah seorang Systems Analyst harus bisa setting router jaringan dan server fisik?"

Tidak harus sampai mengonfigurasi kabelnya sendiri. Namun, Analis wajib memahami kapasitas, batas kecepatan, dan risiko kegagalan perangkat tersebut agar tidak membuat rancangan sistem yang mustahil dieksekusi di lapangan.

Tanya Jawab Umum 2

"Kapan sebuah UMKM harus pindah dari On-Premise ke Cloud?"

Saat volume transaksi harian mulai tidak terduga, toko membuka cabang baru di luar kota, atau saat biaya perawatan server fisik di kantor sudah lebih mahal daripada biaya langganan cloud bulanan.
